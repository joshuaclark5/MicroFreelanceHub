G00 MANDATORY OPERATING RULES

Instructions OpenClaw must follow first

Apply these rules to every checkbox in every module. Reuse verification evidence when it covers several related requirements.

Inspect each requirement before changing code

[ ] G00-001  Before implementing EVERY checkbox, locate the existing screen, route, handler, data model and relevant provider job. Test the stated behavior. Never assume a capability is missing because it was absent from public copy.

[ ] G00-002  If the existing capability satisfies the requirement, record its location and test evidence, mark Existing verified, check the box and immediately move to the next requirement. Do not rebuild, rename or duplicate it.

[ ] G00-003  If the capability is partial, retain working code and records and add only the missing behavior. A working calendar lacking recurrence needs recurrence, not a replacement calendar.

[ ] G00-004  If absent, implement the specified behavior using the established application architecture. Do not create another client database, invoice ledger, permission system or background scheduler when an appropriate one already exists.

[ ] G00-005  Treat equivalent existing labels, layouts and routes as valid when they deliver the stated behavior. Preserve useful extra dropdown options; do not remove them solely to match this proposed default specification.

[ ] G00-006  If blocked by credentials, entitlement, provider approval or an unresolved dependency, leave the box empty, record the precise blocker and continue independent work. A blocker is not evidence of completion.

[ ] G00-007  Inspect mobile behavior, persistence and server permissions before skipping a feature. A visible menu, provider configuration field or mocked demonstration alone does not establish working functionality.

Bind the correct environment and preserve working data

[ ] G00-008  Read repository instructions and identify the repository, active branch, deployed commit, production URL, staging URL, database and provider modes. Resolve a read-only or unbound workspace before making environment-specific changes.

[ ] G00-009  Use an isolated branch and retain the pre-change commit and recoverable backup reference. Preserve unrelated changes, client records, signed agreements, historical invoices and existing subscriptions.

[ ] G00-010  Create synthetic identities for two unrelated businesses, an assigned team member and a client. Verify existing authentication and tenant isolation before connecting new records or exposing client views.

[ ] G00-011  Inventory current provider connections and verify their real capabilities without printing secrets. Distinguish production, sandbox, test-only and unavailable integrations in both implementation and user-facing status.
